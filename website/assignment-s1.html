S1.2 Rehearse null, boundaries and a prediction record

beginner/WorkshopWarmup.java
import java.util.LinkedHashMap;
import java.util.Map;

public class WorkshopWarmup {
    static String explainDays(Integer days) {
        if (days == null) { return "REJECTED: days is required"; }
        if (days < 0 || days > 14) { return "REJECTED: days must be 0 to 14"; }
        int chargeNgn = days * 25;
        return "ACCEPTED: " + chargeNgn + " NGN";
    }

    public static void main(String[] args) {
        Integer[] inputs = {null, -1, 0, 1, 14, 15};
        for (Integer days : inputs) {
            System.out.println(days + " -> " + explainDays(days));
        }

        Map<String, String> prediction = new LinkedHashMap<>();
        prediction.put("case", "zero days");
        prediction.put("expected", "accepted with zero charge");
        System.out.println("Prediction only: " + prediction);
        System.out.println("This program sends no HTTP and opens no database.");
    }
}

S1.3 Write your equipment API acceptance contract

One Asset record represents an equipment type and how many units are available. This inventory exercise does not implement bookings or checkout workflows. Store id, name, units, category. The input contains exactly name, units and category; the server generates id.

examples/new-asset.json
{"name":"Webcam","units":3,"category":"Media"}
examples/updated-asset.json
{"name":"HD Webcam","units":0,"category":"Peripherals"}
FieldRequired ruleExamples
nameRequired JSON text, 1–60 UTF-16 code units after trim; nonblank.Webcam valid; spaces or 61 ordinary letters invalid.
unitsRequired JSON integer 0–50 inclusive; use Integer in input.0 and 50 valid; missing/null/-1/51/decimal/quoted/boolean invalid.
categoryRequired JSON text, 1–30 code units after trim; nonblank.Media valid; missing, spaces or 31 ordinary letters invalid.
idGenerated positive identifier; response/path only.Reject a client id property; do not use row count as an id.
Request at loopback port 8100Successful resultRejection/empty result
GET /api/assets200 JSON array; optional case-insensitive exact category filter after trim.Empty search gives []; missing/blank category gives all.
GET /api/assets/{id}200 JSON record.Absent positive id 404; nonpositive numeric id 400.
POST /api/assets201 after commit, saved JSON and absolute Location.Bad mapped input 400; no new row.
PUT /api/assets/{id}200 after complete replacement/commit; stable id.Valid absent id 404, no upsert; incomplete input 400.
DELETE /api/assets/{id}204 after deletion/commit; empty body.Absent 404; nonpositive numeric id 400.

Duplicated names are allowed. JSON input/output is supported; text/plain request bodies give 415, XML Accept gives 406, and malformed JSON gives 400. Reuse strict JsonSupport to reject unknown properties, wrong scalar types and trailing JSON values. For mapped PUT input check positive id, then body rules, then existence. Framework errors can have a different body shape from your JSON application errors.

YOU PLAN

Write one valid and one invalid request for each writable field, plus a partial PUT and absent id. Say which layer rejects it and what must remain unchanged. Keep the model name Asset distinct from the actual campus_assets table name.

starter-config/src/main/java/com/aptech/assignment/asset/Database.java
package com.aptech.assignment.asset;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;
import java.util.Map;
import jakarta.persistence.EntityManagerFactory;
import jakarta.persistence.Persistence;

// Reusable environment support; learners implement their own entity/store/resources.
public class Database {
    public static EntityManagerFactory open() throws IOException {
        Path base = Path.of(System.getProperty("assets.db", "./data/assets"))
                .toAbsolutePath().normalize();
        Files.createDirectories(base.getParent());
        String url = "jdbc:h2:file:" + base.toString().replace('\\', '/');
        System.out.println("Database file: " + base + ".mv.db");
        return Persistence.createEntityManagerFactory("assets-workshop",
                Map.of("jakarta.persistence.jdbc.url", url));
    }
}

The helper resolves assets.db (default ./data/assets) from the current folder, prints the absolute .mv.db filename and passes its JDBC URL to persistence unit assets-workshop. H2 adds the extension. Reuse this helper; implement your entity/operations yourself. Use one personal file per learner and no startup clearing/seeding. Automatic schema update and the local H2 account are the same course-lab settings.

Copy Session 7’s JsonSupport.java into this package, change its package declaration and register it with JacksonFeature. Its generic mapper configuration does not contain product field names. Keep fail-on-unknown/trailing data and scalar coercion settings while writing your own AssetInput rules.

S1.6 Implement persistence in small operations

Map Asset to campus_assets, with columns asset_id, asset_name, available_units and asset_category. Use a generated positive id. The JPA entity needs its supported construction/mapping access pattern; keep input DTO and response snapshot separate.

Operation you writePlan before codingPractical proof
createValidate/normalize; begin transaction; persist; commit; make response snapshot.Saved actual id; a new process reads it.
find/listUse an operation-local context; snapshot values before close.Absent id handled without dereferencing null; empty list is valid.
category filterUse parameter-bound JPQL over entity/property names with normalized case-insensitive equality.Trim/case variations and empty matches work.

JPQL uses Asset and Java properties, not campus_assets or available_units. Bind user text as a query parameter. Close each EntityManager in finally, roll back an active failed write transaction, and close the factory when its process ends.

A small transaction-plan hint, after your own attempt

Write the steps in words before Java: open context → begin → find/persist/change/remove → commit → snapshot → close. In a failure path, if the transaction is still active, roll it back before closing. Adapt an earlier JPA pattern without pasting its Student/Book application methods as your final solution.

S1.7 Prove rollback explicitly and distinguish it from validation

A rejected body should never change the record. That proves validation/order, but it does not prove transaction rollback. Your console rollback demonstration deliberately changes a managed record and then cancels the transaction.

StepWhat you predict
Stop HTTP A; record a committed asset’s units and actual id.Only one process owns this H2 file.
Open a context and begin a transaction; find that actual id.The current record is managed in this context.
Set a different valid units value and call flush.Changes are synchronized within the transaction, not committed.
Roll back; close context/factory.The temporary change is cancelled.
Start a fresh read/process with the same database file.Original committed units remain.

Implement the demonstration as AssetRollbackDemo, with an actual positive id argument and a useful clue for an absent record. Do not expose a public rollback/debug endpoint. Generated database identity values can have gaps after rolled-back inserts; rejection proof concerns no unintended rows/field changes, not a consecutive database id counter.

EXPLAIN WITHOUT THE METHOD

Why is flush not commit? Why is a following read in a new context stronger evidence than printing the changed managed object before rollback? Why must the server be stopped for this console file-database exercise?

S1.9 Prove complete replacement, filters and selective deletion

curl.exe -i -X PUT "$ws1ItemUrl" -H "Content-Type: application/json" --data-binary "@examples/updated-asset.json"
curl.exe -i "$ws1ItemUrl"
curl.exe -i "http://127.0.0.1:8100/api/assets?category=Media"
curl.exe -i "http://127.0.0.1:8100/api/assets?category=peripherals"

Expect 200 with the same id, name HD Webcam, units 0 and category Peripherals. The updated item must leave the Media filter and appear in a case-insensitive Peripherals filter. Other matching records can still appear. Repeat the identical PUT; it must not add rows. Zero units is valid stock information, not a missing value.

Write a second valid request file with a different equipment name, create it, and record its actual Location separately. Preserve the first asset for restart proof. Use the second Location in a different variable:

$ws1DeleteUrl = Read-Host "Paste the second asset Location"
curl.exe -i -X DELETE "$ws1DeleteUrl"
curl.exe -i "$ws1DeleteUrl"
curl.exe -i -X DELETE "$ws1DeleteUrl"
curl.exe -i "$ws1ItemUrl"

Deletion gives 204 with an empty body, then GET and repeated DELETE give 404. The survivor still has its complete updated values. Stop/restart A in the same folder/file and prove the update remains committed and the second item remains absent. This differs from Session 7’s deliberately temporary Map reset.
